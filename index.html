AI Roadmap

Goal: get really good at using AI, not just know about it. SQL is already my edge (it lets me catch when AI is wrong), so Python is only "read it, don't memorize it". The main track is prompting, context and agents, then building and evals to prove it. Every resource says exactly how much of it to do. Click a phase to expand it.

0
Read code, don't memorize it (1 week) Foundation

Claude writes most of my code now, so the goal isn't writing Python from memory. It's being able to read what AI writes and tell when it's wrong. SQL I already have, and it's my edge: I can catch a bad join in seconds. Python just needs to stop being scary. Target: about 1 week of evenings.

// what to read or watch, and how much
ONLY PART
pandas "Comparison with SQL"
Read only the SELECT, WHERE, GROUP BY and JOIN sections (~30 min). It shows the pandas version of SQL I already know. Skip the rest.
SKIP
Automate the Boring Stuff
Don't read it front to back. Only open a chapter if I hit something in Python I truly can't follow, even after asking Claude to explain it.
// done when
Install Claude Code and have it write a small Python script that does something I'd normally do in SQL (filter, group, join two CSVs)
Go through that script and explain every line out loud. Any line I can't explain, ask Claude why it's there until I can
Ask Claude to put a bug in the script on purpose, then find it myself without asking
Git basics, just enough to read what Claude does: commit, branch, push, and reading a diff
Know the safety basics: API keys go in a .env file that never gets committed
1
How LLMs actually behave (2 weekends) Foundation

Not the math, just enough to know why AI does what it does: why it makes things up, why long chats get worse, why the same question gets different answers. Knowing this changes how I use it every day. Hard time limit of 2 weekends.

// what to read or watch, and how much
READ ALL
Karpathy, "Intro to Large Language Models"
Watch the whole thing (~1 hour). Best short overview of what an LLM actually is.
READ ALL
Karpathy, "How I use LLMs"
Watch the whole thing (~2 hours, split over 2 sittings, 1.25x speed is fine). This is the most directly useful video for me: a power user showing how he actually uses these tools.
SKIP
Karpathy, "Deep Dive into LLMs"
3.5 hours on how models are trained. Interesting, not needed. Skip unless I'm curious later.
OPTIONAL
3Blue1Brown neural networks series
Optional. If I want the visual version, watch only the chapter "But what is a GPT?". Skip the rest.
// done when
Explain tokens and the context window, and why long inputs cost more and get less reliable
Explain why models hallucinate: they predict likely text, not true text
Know when to start a fresh chat instead of continuing a long, messy one
Explain all of it out loud in 5 minutes without notes

Prompting and context Using AI

The core skill. Good prompts are less about clever wording and more about giving the AI the right context: what I want, why, what good looks like, and examples. Target: about 2–3 weeks, roughly one tutorial chapter per evening.

// what to read or watch, and how much
READ ALL
Anthropic's interactive prompt engineering tutorial
Do chapters 1–9, all of them, with the exercises (that's where the learning is). Skip the appendix for now. It also has a Google Sheets version if I don't want to set up notebooks.
READ ALL
Anthropic, "Effective context engineering for AI agents"
Read the whole article (~20 min) after finishing the tutorial. It explains why context matters more than wording.
REFERENCE
Claude prompt engineering docs
Reference only. Don't read it cover to cover. Look up a specific technique when I need it.
// done when
Finish tutorial chapters 1–9 with the exercises
Take 5 prompts I actually used this month, rewrite them with what I learned, and compare the answers side by side
Start a prompt library: a text file of 5+ prompts I reuse, each with a note on why it works
Make it a habit: before asking anything big, write down what I want, why, and what a good answer looks like

Agents, tools and MCP Build

An agent is a model using tools in a loop: plan, act, check the result, repeat. Knowing how they work under the hood makes me much better at using them, and lets me build my own. This is where my old SQL explainer idea lives. Target: about 3–4 weeks.

// what to read or watch, and how much
READ ALL
Anthropic, "Building effective agents"
Read the whole article (~25 min). Main takeaway: start simple, and most problems don't need a complex agent.
ONLY PART
Anthropic Academy: "Building with the Claude API"
Do only 3 sections: "Accessing Claude with the API", "Tool use with Claude" and "Agents and workflows". Skip RAG, the Claude features section and MCP for now (I'll come back to evals in Phase 5).
READ ALL
Anthropic Academy: "Introduction to Model Context Protocol"
Do the whole course. MCP is how AI tools connect to other apps and data, and it's everywhere now.
// done when
Call the Claude API from Python (with Claude Code's help) and get structured JSON back
Build the SQL explainer: a tool that reads a folder of .sql files and writes a plain-English doc for each (purpose, tables, logic, open questions). Use my own sample SQL, not work code
Give it a tool: let the model look up a table's columns instead of guessing
Write a simple agent loop by hand, no framework, so I know what frameworks do for me
Connect an MCP server to Claude (GitHub or Snowflake on a free trial) and use it for a real task
5
Evals: my edge Build

Evals means testing whether AI answers are actually right, at scale, instead of eyeballing a few. It's basically data reconciliation pointed at AI output, which is literally my day job. Most people skip this. Target: about 2–3 weeks.

// what to read or watch, and how much
READ ALL
Hamel Husain, "Your AI Product Needs Evals"
Read the whole post (~30 min). The most practical writing on evals out there.
ONLY PART
Anthropic Academy: "Building with the Claude API"
Do only the "Prompt evaluation" section (typical eval workflow through code-based grading). The rest I've either done or skipped on purpose.
// done when
Build a golden set: 20–30 SQL scripts where I've written the correct answer myself (which tables it reads, what it outputs)
Score the SQL explainer on it: exact-match checks for hard facts, a second model grading the fuzzy parts
Store every run's score in a table and check whether a prompt change actually helps
Read the failures by hand, group them by type, and write up what I learned on this site
